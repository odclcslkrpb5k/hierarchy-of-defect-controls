# Changelog

Each entry is the response to one adversarial review round; the reviews themselves are in `docs/reviews/`.

## 0.7.0

Independent protection layers, the qualitative half of Layer of Protection Analysis (`docs/protection-layers.md`). Independence is judged by where a check's expected answer came from, not by who wrote it or when: pre-existing unmodified tests, untouched type checkers and linters, checks against captured real output, and reviews without the author's framing count; a test written from the agent's own reading of the problem, the agent's self-review, and any check the change edits do not. One CI workflow file is named as the common mode of lint, types and tests. The plugin's own controls are assessed and none is an IPL. Two rules added to `docs/CLAUDE.md` and the skill (Administer): run the pre-existing checks unmodified and report them apart from your own tests; do not weaken a check so your own change passes unless asked, and name every check you changed. No hook behaviour changed; only the version constant.

Access security is a Claude Code permission setting, not a hook: plugins cannot ship permission rules. It was tested before being documented (`docs/evidence/permission-rules-2.1.289.md`): in `-p` on 2.1.289, a `deny` rule on `Edit(/.github/workflows/**)` blocked the edit tools, `echo >>`, `sed -i`, `rm` and `mv`, but not a Python script opening the file; an `ask` rule blocked only the edit tools. The doc therefore recommends `deny` and says what neither covers.

The plan was red-teamed by a separate session before any of it was written. Taken from it: the method is named for what it is, since LOPA without failure probabilities is IPL qualification; the permission rule is labelled Engineer, not Substitute (the draft repeated review 00's misclassification of the Stop hook); independence by oracle, replacing a draft rule by session and author that contradicted `docs/CLAUDE.md`'s own fixture-validated example; a planned script that printed the settings snippet, a "same-session tests and code" indicator that rewarded writing no tests, and a rule to "stop for the user" (no user in `-p` or subagents) were all cut; the live check was made a precondition. The red team expected `rm` and `mv` to get past a deny rule; the live check found they do not.

## 0.6.1

Round-6 should-fix items; the review passed 0.6.0 with no blockers. R8: `DENY_RE` cut the signature at the first `")`, so an error quoting a call (`ValueError("bad input")`) split one loop into two episodes; it now anchors on the `") and ` that follows the signature in every version. R9: `import traceback` moved into the one `except` that uses it, removing about 12 ms from every hook run. R10: only the locked state read records a corrupt file, so one corruption is one record, not one per unarmed gate call. R11: the Tier 4 log refuses symlinks (`lstat`, `O_NOFOLLOW`). F3: the docs no longer claim the log write cannot block (a hung filesystem can block it, as it can the state file), count trailer-only repos correctly (7 of 8), and say the wrapped deny form has been seen only in `-p` sessions; the report now prints the Claude Code versions it read, so a version newer than the fixtures is visible. F4: tests that a missing `HDC_EVENTS` opens no file anywhere, that a FIFO with a reader is still refused, and that `traceback` stays off the hot path; the in-process test imports no longer leave `scripts/__pycache__`. Each new test was mutation-checked against the bug it guards. Fixing R8 exposed three synthetic deny strings in the tests that lacked the real message's tail; one test had passed only because neither of its denies parsed.

## 0.6.0

Indicators, an analog of API RP 754 (`docs/indicators.md`). `scripts/hdc_report.py` is a read-only CLI over Claude Code transcripts: Tier 3 demands on the controls (gate denies, reminders, no-op detections) grouped into episodes, exposure in tool calls, episodes that continued past the gate, and denies cleared by a user turn as the gate's cost; a rate only from 20 episodes, with an exact Poisson interval. Tier 4 is an opt-in `HDC_EVENTS` log of hook exceptions that were swallowed silently and of corrupt state files, written non-blocking and without command text. The deny, reminder and no-op strings are now constants shared by hooks and report, emitted byte-identically. No hook decision changed, and nothing reaches the model's context.

The design was red-teamed at plan stage by a separate session. Taken from it: Tier 3 read from transcripts instead of logged by the hooks, which drops a SessionEnd hook whose exposure count lost killed sessions and double-counted resumed ones; Tiers 1 and 2 left as definitions (no reverts in 372 agent-trailer commits measured); `--no-verify` detection, a fingerprint-error distinction and a missing-field check cut as new false-positive surface; episodes instead of raw events; the report kept out of `main()`, whose swallow-all would print an empty report on a bug. Changed from it: a deny re-run after a user turn is reported as the gate's cost, not as a false deny, since that is the gate's designed escape. Found while testing against real transcripts: a Bash call that printed a captured deny message counted as a deny; denies now require `is_error`. Found in the live check: Claude Code 2.1.289 stores a deny as `PreToolUse:Bash hook error: <reason>`, which the report missed until it accepted the wrapper; a second transcript fixture from 2.1.289 now covers it. Also seen live: headless `-p` payloads carry no `scratchpad_dir`, so state falls back to the system temp directory through `state_path`'s existing fallback.

## 0.5.1

Round-5 should-fix items. The four perl switch-parsing tests, dropped by mistake in 0.5.0 when the patch tests were rewritten, are restored and mutation-checked (replacing `perl_inplace` with `"i" in tok` fails two of them). ## 0.5.0

Round-4 blocker: `git apply` and `patch` removed from the no-op detector. The branch's only true positive was an empty patch, since a re-applied patch fails in every form tested and the gate already handles that; its false positives (`--cached`, rename, mode and binary patches, explicit `patch` targets, `git apply` from a subdirectory, after gitignored and out-of-repo targets in earlier rounds) met the package's own removal condition for a narrow gate. Tests now assert that patches are never flagged and that a re-applied patch reaches the gate through the failure path. Also: output with no error-like line signs with its first and last non-decoration lines instead of the first alone; a conditional assertion in the hex-id test replaced with explicit ones; `__pycache__` excluded when the tarball is built.

## 0.4.0

Round-3 blockers: perl and sed switch clusters are parsed so `-Ilib`, `-Mstrict`, `-e` no longer read as `-i` (read-only perl was reported as a no-op and denied on the third run); `git apply` and `patch` now hash the target files parsed from the patch instead of comparing the tree fingerprint (real patches outside git or to gitignored files were reported as no-ops). Should-fix: banner-framed lines and the `Traceback` header are decoration, signatures use the first and last error-like lines (unrelated Python and pytest failures shared a signature; a changed exception did not restart the gate count); compound detection uses shlex punctuation tokens so quoted `|` and `;` in a sed script no longer skip detection; fixtures replaced with captured payloads; README wording on `git status` and on patch targets corrected.

## 0.3.0

Blocking fixes from the round-2 review: `git diff` and `git diff --cached` replaced by `diff-files -p` and `diff-index -p --cached` under `GIT_OPTIONAL_LOCKS=0` (porcelain diff rewrote the index and made concurrent user commits fail on `index.lock`; empty-tree base for unborn `HEAD`). Marker extended with `HEAD` and the edit epoch (fixes by `git checkout` or by Edit to a gitignored file did not reopen the gate). No-op detector rewritten: `sed`/`perl` operands hashed before and after (real edits to gitignored and out-of-repo files were reported as no-ops), compound commands and dry-run flags skipped. Should-fix items: fingerprint computed lazily and outside the lock; signatures skip decoration lines and prefer error-like lines, output-less failures keyed by command word, hex and UUID ids normalised; "previous remedy was too low" removed from the reminder; no-op detector relabelled; documented-gaps list moved out of the test suite into this README; fixtures split into per-event files.
