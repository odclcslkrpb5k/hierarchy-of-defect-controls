## 1. Correctness

### R2a. Perl switches containing `i` are treated as in-place edits — BLOCKING

- **Where:** [scripts/hdc_hooks.py:189-195](hierarchy-of-defect-controls/scripts/hdc_hooks.py#L189-L195)
- **Failure mode:** in-place detection is `"i" in t[1:]` for any short-option token, so any perl switch whose text contains `i` counts:
  - `-Ilib` (module path)
  - `-Mstrict`
  - `-MList::Util=sum`
  - `-MFile::Spec`

  Every existing-file operand is hashed. A read-only command leaves them unchanged, so the call is recorded as a failure, the model is told "the replacement matched nothing", and the third identical run is denied.
- **Confirmed (ran):**

  | Command (all read-only, all exit 0) | Result |
  |---|---|
  | `perl -c -Ilib lib/Foo.pm` #1 | flagged: "reported success but its target is byte-identical … the replacement matched nothing" |
  | `perl -c -Ilib lib/Foo.pm` #2 | flagged, failure 2 |
  | `perl -c -Ilib lib/Foo.pm` #3 | **DENIED** |
  | `perl -Mstrict -ne 'print if /foo/' x.txt` | flagged |
  | `perl -MList::Util=sum -lane 'print $F[0]' x.txt` | flagged |

- **Confirmed (real session, step 18):** `perl -c -Ilib lib/Foo.pm` printed `lib/Foo.pm syntax OK` and got the no-op message. The model identified the cause in its report: "It seems to treat `-i` in `-Ilib` as an in-place edit flag."
- **Harm:** false statements to the model on common read-only perl invocations: syntax checks, `perl -Ilib t/foo.t`, one-liners with `-M`. A repeated check with no change in between is denied.
- **Fix:** parse perl switch clusters character by character. `i` means in-place only when it appears as a switch before the cluster reaches a switch that takes an argument:
  - Switches that take an argument, so everything after them in the cluster is that argument: `0 C d D e E F i I l m M x V`.
  - `i` itself takes an optional backup-extension argument. So `-pi`, `-i`, `-i.bak` and `-pi.orig` are in-place; `-Ilib`, `-Mstrict` and `-e` are not.
  - For `sed`, keep the current rule but require the token to be exactly `-i`, `-i<suffix>`, or a cluster of switches that take no argument ending in `i` (`-ni`, `-Ei`). Or restrict to `-i*` and `--in-place*`.

### R2b. `patch` / `git apply` outside git, or to gitignored files, reported as no-ops — BLOCKING

- **Where:** [scripts/hdc_hooks.py:206-209](hierarchy-of-defect-controls/scripts/hdc_hooks.py#L206-L209) (tree plan) and [scripts/hdc_hooks.py:466-467](hierarchy-of-defect-controls/scripts/hdc_hooks.py#L466-L467) (comparison).
- **Failure mode:** for `git apply` and `patch`, the detector compares the marker before and after.
  - **Outside git:** the marker is `nogit:e<epoch>`, identical before and after unless an Edit tool ran. Every real patch is reported as a no-op. v0.2.0 guarded this with `before.startswith("git:")`, and v0.3.0 dropped the guard.
  - **Inside git, gitignored target:** the tree fingerprint doesn't change either.
- **Confirmed (ran):**

  | Command | What actually happened | Hook said |
  |---|---|---|
  | `patch -p1 < fix.patch` (no git repo) | `x.txt` now `bar` | "target is byte-identical … matched nothing" |
  | `git apply fix.patch` (no git repo; `git apply` works outside repos) | `x.txt` now `bar` | same |
  | `patch -p1 < ../env.patch` (repo, `.env` gitignored) | `.env` now `bar` | same |

- **Fix:** handle patches like `sed` operands. Parse the patch file to get the target paths:
  - the positional argument, or the token after `<`, or `-i <file>` for `patch`
  - target paths are the `+++ b/<path>` lines, with `-p<n>` stripping applied, or `--- a/<path>` for deletions

  Hash those files before and after. If the patch file can't be read or parsed, skip detection. That covers outside-git, gitignored and out-of-repo targets, and needs no git. If the tree plan is kept as a fallback, restore the `git:` guard.

### R5. Error signatures still collide for Python tracebacks and pytest output — should fix

- **Where:** `pick_error_line` / `error_signature`, [scripts/hdc_hooks.py:101-127](hierarchy-of-defect-controls/scripts/hdc_hooks.py#L101-L127), with `ERRORISH_RE` and `DECORATION_RE` at [lines 75-76](hierarchy-of-defect-controls/scripts/hdc_hooks.py#L75-L76).
- **Failure mode:** the signature uses the *first* error-like line. `DECORATION_RE` only excludes lines made entirely of punctuation, so a banner with words in it is not decoration.
  - **Python:** the first error-like line of every traceback is `Traceback (most recent call last):`.
  - **pytest, default output:** the first error-like line is `=================================== FAILURES ===================================`.
  - **pytest output with no failure section:** no line matches, so the fallback picks the first non-decoration line, which is `==== test session starts ====`.
- **Confirmed (ran):**
  - **N3:** `python3 a.py` (KeyError), then `python3 b.py` (ModuleNotFoundError) → reminder "failed 2 times … same signature: "exit 1: traceback (most recent call last):"".
  - **N3b, gate side:** same `python3 c.py`, ModuleNotFoundError on run 1. The error became KeyError on run 2, because a file outside the repo changed. Both recorded as `exit 1: traceback (most recent call last):`, count 2, and run 3 **DENIED**. README.md:33 says the gate arms only on the *same error*; for Python every exception is the same error. (Run 3 was unchanged since run 2, so the denial itself is defensible. The problem is that a *changed* error should restart the count, and doesn't.)
  - **E7 (round-2 harness):** two pytest commands with banner-first output → reminder with signature `exit 1: ======…`.
  - **pytest standard default output** ([below](#r5-pytest-output-used)) for two different tests → both signatures `exit 1: =================================== failures ===================================`.
- **Why the package's test passes:** [test/run_tests.py:329-333](hierarchy-of-defect-controls/test/run_tests.py#L329-L333) uses output with `FAILED tests/test_a.py::t` as the first error-like line, and no `FAILURES` banner.
- **Fix:**
  1. Treat banner-framed lines (`^[=\-_*#~]{3,}\s.*\s[=\-_*#~]{3,}$`) as decoration.
  2. Skip `Traceback (most recent call last):`.
  3. Build the signature from the first **and** last error-like lines. The last line of a Python traceback is the exception, and a pytest run's first remaining line is its `E   AssertionError: …` line.
  4. Replace the test fixture with real pytest and Python output, captured on a machine where pytest runs.

### R8. The compound-command check runs on the raw string, including quoted text — low

- **Where:** `COMPOUND_RE` at [scripts/hdc_hooks.py:73](hierarchy-of-defect-controls/scripts/hdc_hooks.py#L73), applied at [line 180](hierarchy-of-defect-controls/scripts/hdc_hooks.py#L180) before `shlex`.
- **Failure mode:** `|` or `;` inside a quoted sed script makes the command "compound", so detection is skipped. `s|a|b|` is a common delimiter, and `s/a/b/;s/c/d/` a common script.
- **Confirmed (ran):** `sed -i 's|zzz|yyy|' x.txt` three times, a genuine no-op each time: never flagged, never blocked.
- **Severity:** fails open, so low.
- **Fix:** tokenise with `shlex.shlex(cmd, posix=True, punctuation_chars=True)`. Treat it as compound only if a token is exactly `&&`, `||`, `;`, `|` or `&`, or the raw string contains an unquoted newline.

## Reproduction

### Harness

Same as round 2. It simulates PreToolUse `gate` → the real command → `success` or `failure`, using real field names.

```python
import json, os, subprocess, tempfile
S = "/abs/path/hierarchy-of-defect-controls/scripts/hdc_hooks.py"
base = tempfile.mkdtemp()
N = [0]

def sh(cmd, cwd): return subprocess.run(cmd, shell=True, cwd=cwd, capture_output=True, text=True)
def hook(mode, p): return subprocess.run(["python3", S, mode], input=json.dumps(p), capture_output=True, text=True).stdout

def mkrepo(name, git=True):
    r = os.path.join(base, name); os.makedirs(r)
    if git:
        sh("git init -q -b main && git config user.email t@t && git config user.name t && "
           "printf 'foo\\n' > x.txt && printf '.env\\n' > .gitignore && git add -A && git commit -qm init", r)
    return r

def bash(r, sid, cmd):
    N[0] += 1
    p = {"session_id": sid, "cwd": r, "scratchpad_dir": base, "tool_name": "Bash",
         "tool_input": {"command": cmd, "description": "d"}, "tool_use_id": f"toolu_{N[0]}"}
    if "deny" in hook("gate", {**p, "hook_event_name": "PreToolUse"}): return "DENIED", ""
    res = sh(cmd, r)
    if res.returncode == 0:
        out = hook("success", {**p, "hook_event_name": "PostToolUse",
                               "tool_response": {"stdout": res.stdout, "stderr": res.stderr, "interrupted": False}})
    else:
        out = hook("failure", {**p, "hook_event_name": "PostToolUseFailure",
                               "error": f"Exit code {res.returncode}\n{res.stdout}{res.stderr}".strip()})
    return f"exit={res.returncode}", (json.loads(out)["hookSpecificOutput"]["additionalContext"] if out else "")
```
