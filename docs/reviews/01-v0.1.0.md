# Review: hierarchy-of-defect-controls plugin (v0.1.0)

Adversarial review, 2026-09-14. The package is judged against its own framework ([docs/hierarchy-of-defect-controls.md](hierarchy-of-defect-controls/docs/hierarchy-of-defect-controls.md)), not against its README's description of itself.

**Verdict: ship with named fixes, not as-is.** Every field the hook script reads exists in real Claude Code payloads, so the top-severity bug class (a misnamed field that silently lets everything through) is absent. But the gate misses the most common retry loops, denies correct calls with deny messages that are false, and two of its rung labels don't match the framework. The fixes required before release are listed in the [verdict](#verdict).

## How this was checked

Each finding says how it was confirmed: **ran** (executed and observed), **docs** (the current hooks reference), **traced** (followed the code path), or **reasoned**.

- **Test suite.** `test/run_tests.sh`: 15/15 pass, exit 0.
- **Hooks reference.** Field names and event semantics come from the raw markdown at `https://code.claude.com/docs/en/hooks.md`, fetched 2026-09-14. No summary was used.
- **Real session.** I ran Claude Code 2.1.270 (`claude -p`) with this plugin loaded alongside a second plugin that appended every PreToolUse, PostToolUse, PostToolUseFailure and PermissionDenied payload to a file. The prompt was a scripted 10-step sequence:
  - `false` three times
  - `grep` with no match
  - `ls` on a missing directory
  - the same failing Edit three times
  - a subagent running `false` twice
  - `false` once more
- **Uncovered inputs.** I fed hand-built payloads to `scripts/hdc_hooks.py` for cases the tests don't cover. The inputs are in [Reproduction](#reproduction).
- **Concurrency.** I ran 13 hook processes at once against one state file, 40 times.

**Not verified:** no successful Edit ran in the real session (all three Edits failed validation), so the success path that bumps the edit epoch was checked only against the test fixture and the documented PostToolUse example.

## 1. Correctness

**Fields.** `tool_name`, `tool_input`, `error`, `session_id` and `scratchpad_dir` all appear in the real 2.1.270 payloads. The PreToolUse deny output is in the documented format. The `description` field really does change on every retry ("Run false command (step 1)", "... (step 2)"), so ignoring it (`IGNORED_INPUT_FIELDS`) is necessary. Confirmed: ran, docs.

The defects are about which events reach the hooks, and how the script interprets them.

### C1. Failed Edits never reach the gate

- **Where:** [scripts/hdc_hooks.py:6](hierarchy-of-defect-controls/scripts/hdc_hooks.py#L6) ("all tools"), [README.md:7](hierarchy-of-defect-controls/README.md#L7)
- **Failure mode:** "String to replace not found in file" is a validation rejection. Claude Code returns it before any hook runs, so neither PreToolUse nor PostToolUseFailure fires. The most common Edit retry loop is invisible to both the gate and the reminder.
- **Confirmed (ran, docs):** three identical failing Edits in the real session. None was blocked, and the payload log has no Edit entries at all. The docs say validation rejections "happen before hooks run, so they fire neither `PreToolUse` nor `PostToolUseFailure`".

### C2. A failed Bash command reported as success clears the failure count

- **Where:** [scripts/hdc_hooks.py:207](hierarchy-of-defect-controls/scripts/hdc_hooks.py#L207), [README.md:45](hierarchy-of-defect-controls/README.md#L45)
- **Failure mode:** two routes deliver a failed command to PostToolUse rather than PostToolUseFailure. In both, `mode_success` deletes the call's failure count.
  - **Exit-code interpretation.** `grep` exiting 1 arrives with `"returnCodeInterpretation": "No matches found"`. The same applies to any command whose non-zero exit Claude Code interprets as non-error.
  - **Pipes.** A pipeline's exit status is its last command's, so `pytest 2>&1 | tail -30` exits 0 when the tests fail. The gate never arms for the most common way of running tests, and each run resets the count.
- **Consequence for the docs:** the README's stated blind spot ("a wrong answer with exit code 0") understates the gap. Non-zero exits hidden by a pipe or by exit-code interpretation are also invisible.
- **Confirmed:**
  - grep routing: ran (real session payload).
  - Pipe exit status: ran (`PIPESTATUS=1 0`, `$?=0`).
  - That a piped failure is routed to PostToolUse: reasoned from the grep case.

### C3. Subagents share the parent session's state file and edit epoch

- **Where:** [scripts/hdc_hooks.py:107-111](hierarchy-of-defect-controls/scripts/hdc_hooks.py#L107-L111)
- **Failure mode:** subagent payloads carry the parent's `session_id` and `scratchpad_dir`. Only `agent_id` differs. Every agent in a session therefore reads and writes one state file.
  - **Wrong denials.** A subagent is denied a call it has never made, and the message tells it the call "has failed 2 times".
  - **Shared epoch, open side.** Any agent's successful Edit reopens every agent's gate, including for unrelated files.
  - **Shared epoch, closed side.** A lost epoch update (C4) blocks every agent after a real edit.
- **Confirmed (ran):** in the real session the main thread ran `false` twice. The subagent's first `false` was then denied with "has failed 2 times in this session". Both subagent payloads show the same `session_id` and `scratchpad_dir` as the parent, plus `agent_id`.

### C4. Concurrent hooks lose updates and can corrupt the state file

- **Where:** [scripts/hdc_hooks.py:114-135](hierarchy-of-defect-controls/scripts/hdc_hooks.py#L114-L135)
- **Failure mode:** `load_state` → modify → `save_state` runs with no lock, and every writer uses the same temporary path, `path + ".tmp"`. The docs say PostToolUse "fires concurrently when Claude makes parallel tool calls", and subagents add more concurrent writers.
- **Confirmed (ran):** 12 failure hooks and 1 Edit-success hook started in parallel against one session, 40 trials. The expected end state is `edit_epoch=1` with 12 recorded calls.

  | Outcome | Trials | Effect |
  |---|---|---|
  | Edit's epoch bump lost | 3 | Gate denies after a real edit |
  | State file left as invalid JSON | 1 | Next load starts from empty state; all counts gone |
  | At least one failure count lost | 39 | Gate arms late or never |

  This contention is heavier than typical (2–5 parallel calls). The race itself is real.

### C5. A fix that changes only whitespace is denied as "unchanged"

- **Where:** [scripts/hdc_hooks.py:73-76](hierarchy-of-defect-controls/scripts/hdc_hooks.py#L73-L76)
- **Failure mode:** `canonical_call` collapses runs of whitespace inside every string before hashing. When whitespace is the fix (indentation, quoted strings, heredocs, `printf` formats), the corrected call hashes the same as the failed one.
- **Confirmed (ran):** a Bash heredoc running Python failed twice with IndentationError. The re-indented command exits 0 when run directly, and the gate denied it. This is the input the test suite doesn't cover; see [Reproduction](#reproduction).

### C6. The reminder fires on any two Bash failures, claiming "the same signature"

- **Where:** [scripts/hdc_hooks.py:49](hierarchy-of-defect-controls/scripts/hdc_hooks.py#L49)
- **Failure mode:** `normalise_error` keeps only the first line of the error. For Bash, the first line is always `Exit code N`, which normalises to `exit code <n>`. Every Bash failure in a session shares one signature, so the second unrelated Bash failure triggers the reminder.
- **Confirmed (ran, docs):** in the real session, `ls /nonexistent_dir_hdc` produced "failed 3 times ... same signature: "exit code <n>" ... This is occurrence 3" after two `false` runs. The docs describe the Bash error as a first line `Exit code N` followed by the output, and say to treat the rest as display text.

### C7. Unexpected `tool_input` fields: the ignore list is wrong in both directions

- **Where:** [scripts/hdc_hooks.py:64](hierarchy-of-defect-controls/scripts/hdc_hooks.py#L64)
- **Extra fields pass the gate (ran).** After `npm install` was denied:
  - `{"command": "npm install", "dangerouslyDisableSandbox": true}` was allowed.
  - `{"command": "npm install # retry: registry timeout"}` was allowed.
- **Real changes are ignored (ran).** Two fields that really change the call are on the ignore list:
  - `{"command": "npm  install", "run_in_background": true}` was denied.
  - A retry with a larger `timeout` is denied; [test/run_tests.sh:33-34](hierarchy-of-defect-controls/test/run_tests.sh#L33-L34) asserts exactly this.
- **Future fields (reasoned).** The design lists fields to ignore rather than fields to key on. Any per-call field Claude Code adds later disables the gate silently, exactly as `description` would have without the list.

### C8. The tests don't exercise real payloads

- **Where:** [test/run_tests.sh:24](hierarchy-of-defect-controls/test/run_tests.sh#L24), [test/run_tests.sh:36](hierarchy-of-defect-controls/test/run_tests.sh#L36)
- **Hand-written fixtures (traced).** The Edit fixture uses `old_str`/`new_str`; the real tool uses `old_string`/`new_string`. No fixture was captured from a real session, which breaks the package's own rule in [docs/CLAUDE.md:19](hierarchy-of-defect-controls/docs/CLAUDE.md#L19).
- **An assertion that cannot fail (traced).** Line 36 checks that `success` mode prints nothing, which it always does. Line 37 covers the actual behaviour.
- **No coverage** of C1–C7.

### C9. The manifest still advertises the removed Stop reviewer

- **Where:** [.claude-plugin/plugin.json:4](hierarchy-of-defect-controls/.claude-plugin/plugin.json#L4)
- **Failure mode:** the description says "a fresh-context reviewer at Stop". The README says it was removed, and `hooks/hooks.json` has no Stop hook.
- **Confirmed:** traced.

## 2. Framework consistency

The framework's test for the Engineer rung: "The mistake is possible, but the system catches it." If a component works only when the model reads text and acts on it, it is Administer ("The system will not stop the mistake; people are asked to").

### F1. The reminder is labelled "Engineer detector, Administer nudge". It is Administer.

- **Where:** [README.md:8](hierarchy-of-defect-controls/README.md#L8)
- **Why:** its only output is `additionalContext` that the model must read and act on. Nothing is caught or stopped. Counting outside the model, and keeping the count through compaction, make it a better Administer control, not an Engineer one. The detector half doesn't hold up either: because of C6 it reports repeats that aren't repeats.
- **Correct label:** Administer.

### F2. The gate is labelled Engineer. Correct for the block, but its scope is overstated.

- **Where:** [README.md:7](hierarchy-of-defect-controls/README.md#L7), [README.md:46](hierarchy-of-defect-controls/README.md#L46), [docs/CLAUDE.md:29](hierarchy-of-defect-controls/docs/CLAUDE.md#L29)
- **What holds:** denying an identical failing Bash or MCP retry is deterministic and doesn't depend on the model reading anything. That part is Engineer.
- **What doesn't hold:**
  - **"It cannot be talked past, only edited past" is false.**
    - A trailing shell comment gets past it (C7).
    - The deny message at [scripts/hdc_hooks.py:236-238](hierarchy-of-defect-controls/scripts/hdc_hooks.py#L236-L238) tells the model to "vary the call".
    - Any edit to any file reopens it, including the `NOTES.md` line that [docs/CLAUDE.md:31](hierarchy-of-defect-controls/docs/CLAUDE.md#L31) tells the model to write.
  - **Its instructions are Administer.** The deny message's "name the rung" and "say so to the user" depend on the model complying, and should be labelled that way.
  - **The false-positive claim doesn't hold.** "Close to the definition of the loop" is contradicted by section 3.
- **Correct label:** "Engineer, narrow: identical failing Bash and MCP retries (not Edit, not piped commands)", with the deny message's instructions labelled Administer.

### F3. The PostToolUse bookkeeping is labelled "support". It is part of the gate.

- **Where:** [README.md:9](hierarchy-of-defect-controls/README.md#L9)
- **Why:** it decides when the gate reopens. Its defects are gate defects: clearing counts on interpreted non-zero exits (C2), losing epoch updates (C4), recognising only four edit tools (H4). Calling it "support" keeps those out of the gate's description.
- **Correct label:** part of the gate's Engineer control.

### F4. "Resolving to be more careful" is given two different rungs

- **Called Protect:** [scripts/hdc_hooks.py:151](hierarchy-of-defect-controls/scripts/hdc_hooks.py#L151) (the injected reminder), [skills/hierarchy-of-defect-controls/SKILL.md:27](hierarchy-of-defect-controls/skills/hierarchy-of-defect-controls/SKILL.md#L27), [docs/hierarchy-of-defect-controls.md:86](hierarchy-of-defect-controls/docs/hierarchy-of-defect-controls.md#L86).
- **Called Administer:** [docs/CLAUDE.md:25](hierarchy-of-defect-controls/docs/CLAUDE.md#L25).
- **Correct rung:** Administer. A resolution made before the next attempt asks the agent not to repeat the mistake. Protect means the defect has shipped and is absorbed downstream.
- **Why it matters:** the plugin's own injected text gives the model the wrong label.
- **Root cause:** the framework doc lists "Be careful" comments under Protect ([line 62](hierarchy-of-defect-controls/docs/hierarchy-of-defect-controls.md#L62)), against its own definitions.

### Labels that are correct

- **The skill:** Administer. If anything it is weaker than a project `CLAUDE.md`, because it loads only when the model matches it.
- **The `NOTES.md` repeat record** ([docs/CLAUDE.md:31](hierarchy-of-defect-controls/docs/CLAUDE.md#L31)): Administer, and labelled as such.

## 3. Harm: where the gate denies a legitimate call

For each case: does the deny message's escape hatch ("vary the call ... say so to the user") handle it, or does the design need to change?

| # | Case | Confirmed | Escape adequate? | Design change |
|---|---|---|---|---|
| H1 | **Transient network error.** `npm install` fails twice with ETIMEDOUT; the third identical run is denied. | ran | **Mostly.** Adding a comment gets through. But the gate then teaches cosmetic evasion, and "say so to the user" is never enforced. | Stop recommending variation in the deny message. Arm the gate only when the call *and* the error signature (exit code + first output line) match across failures. |
| H2 | **Success depends on external state.** Polling a server that is still booting, `gh run view`, `kubectl rollout status`, or the user saying "I restarted Postgres, try again". | reasoned | **Yes when the model is polling** (`sleep 5 && ...` is a different call). **No when the user acted outside the session:** the user can't reopen the gate, and "no file has been edited" is irrelevant. | Clear the failure counts on `UserPromptSubmit` (documented event). A new user turn is new external state. |
| H3 | **Retry with a larger timeout.** Two "Command timed out after 2m 0s", then a retry with `timeout: 600000` is denied. | ran (C7) | **No.** Raising the timeout is the correct change, and the gate treats it as unchanged. | Remove `timeout` and `run_in_background` from `IGNORED_INPUT_FIELDS`. |
| H4 | **File changed by a tool not in `EDIT_TOOLS`.** `sed -i`, `git apply`, `eslint --fix`, a generator script, or the user editing in their IDE. | traced | **No.** The gate stays closed, and "no file has been edited since the last failure" is false. That tells the model its fix didn't take. | Replace the edit epoch with a working-tree fingerprint (hash of `git status --porcelain=v1 -z` and `git diff`), recorded at failure time and compared at gate time; use the epoch outside git. The `FileChanged` event can't replace it: it watches only filenames listed in its matcher. |
| H5 | **An MCP tool that writes files** (filesystem, JetBrains and similar servers). | traced | **No.** [README.md:39](hierarchy-of-defect-controls/README.md#L39) asks the installer to add tool names to `EDIT_TOOLS`, which is itself an Administer control. | Same fingerprint fix as H4. |
| H6 | **Fix that changes only whitespace.** | ran (C5) | **No.** The correct call is denied as identical. | Hash string values exactly as sent. |
| H7 | **Subagent denied a call it never made.** | ran (C3) | **No.** The message's claim that the call "has failed 2 times" is false for that agent. Parallel subagents running the same test suite hit this routinely. | Key failure counts by `agent_id`. Keep the file-change check shared, since files are shared. |
| H8 | **Denied right after a real edit because the epoch update was lost.** | ran (C4) | **Not applicable;** this is a bug. | `fcntl.flock` around load-modify-save, and a unique temporary file name per writer. |

### The gap left by the removed Stop reviewer

The gap is still open. The silent repeat the package's own docs name ([docs/CLAUDE.md:29](hierarchy-of-defect-controls/docs/CLAUDE.md#L29)) is "a replacement that matched nothing reports success". Re-adding a prose reviewer is ruled out; one deterministic check covers this case:

**No-op in-place edit detector.**

1. **PreToolUse, Bash only.** If the command matches an in-place-edit pattern (`sed -i`, `perl -pi`, `git apply`), record the working-tree fingerprint from H4, keyed by `tool_use_id`.
2. **PostToolUse.** Compare the fingerprint. If the command succeeded but the fingerprint is unchanged, record the call as a failure in the state file.
3. **Result.** Because the call is now recorded as a failure, the existing gate blocks an identical retry.

The recording is deterministic and reads no prose. It reuses the H4 fingerprint.

## Verdict

**Ship with named fixes, not as-is.** The core mechanism works: in a real session the gate blocked a third identical failing Bash call, with the documented output format. But the package is weaker than it claims in both directions:
- **It misses the loops it targets:** failed Edits (C1) and piped test runs (C2).
- **It denies correct calls, with deny messages that are false:**
  - subagents (H7)
  - whitespace fixes (H6)
  - timeout raises (H3)
  - fixes applied through Bash or MCP (H4, H5)
  - retries after the user fixed something outside the session (H2)

That breaks the framework's own proportionality rule for narrow gates.

**Required before release:**

1. Key failure counts by `agent_id` and lock the state file (C3, C4, H7, H8).
2. Hash string values exactly as sent. Stop ignoring `timeout` and `run_in_background` (C5, C7, H3, H6).
3. Build the Bash error signature from the exit code plus the first output line (C6).
4. Clear failure counts on `UserPromptSubmit` (H2).
5. Replace the edit epoch with a working-tree fingerprint (H4, H5).
6. Correct the labels and claims:
   - Relabel the reminder as Administer (F1).
   - State the gate's narrow scope, and label its message instructions Administer (F2).
   - Use Administer for "be more careful" everywhere (F4).
   - Correct [docs/CLAUDE.md:29](hierarchy-of-defect-controls/docs/CLAUDE.md#L29) and [README.md:45-46](hierarchy-of-defect-controls/README.md#L45-L46).
   - Remove the Stop reviewer from `plugin.json` (C9).
7. Rebuild the test fixtures from captured payloads. Add tests for C1–C7 (C8).

With those fixes the gate's Engineer label holds. Without them, the plugin adds friction exactly when the model is right, and still misses the loops it was built for.

## Reproduction

All commands run from the repository root. `S` is the hook script; `TMPDIR` isolates the state file.

```bash
S=hierarchy-of-defect-controls/scripts/hdc_hooks.py
export TMPDIR=$(mktemp -d)
```

**C5 / H6: a whitespace-only fix is denied.**

```bash
python3 - "$S" <<'EOF'
import json, subprocess, sys
S = sys.argv[1]
def run(mode, p):
    return subprocess.run(["python3", S, mode], input=json.dumps(p),
                          capture_output=True, text=True).stdout
bad  = "python3 - <<'PY'\nfor i in range(3):\nprint(i)\nPY"       # IndentationError, exit 1
good = "python3 - <<'PY'\nfor i in range(3):\n    print(i)\nPY"   # exit 0
fail = {"session_id": "w", "hook_event_name": "PostToolUseFailure", "tool_name": "Bash",
        "tool_input": {"command": bad}, "error": "Exit code 1\nIndentationError"}
run("failure", fail); run("failure", fail)
out = run("gate", {"session_id": "w", "hook_event_name": "PreToolUse",
                   "tool_name": "Bash", "tool_input": {"command": good}})
print("DENY" if "deny" in out else "allow")    # prints DENY
EOF
```

**C7: extra fields pass the gate; `run_in_background` is ignored.**

```bash
f='{"session_id":"x","tool_name":"Bash","tool_input":{"command":"npm install"},"error":"Exit code 1\nnpm ERR! network ETIMEDOUT"}'
echo "$f" | python3 $S failure >/dev/null; echo "$f" | python3 $S failure >/dev/null
for ti in '{"command":"npm install","dangerouslyDisableSandbox":true}' \
          '{"command":"npm install # retry: registry timeout"}' \
          '{"command":"npm  install","run_in_background":true}'; do
  r=$(echo "{\"session_id\":\"x\",\"tool_name\":\"Bash\",\"tool_input\":$ti}" | python3 $S gate)
  echo "$ti -> ${r:+DENY}${r:-allow}"
done
# allow, allow, DENY
```

**C6: unrelated Bash failures share one signature.**

```bash
echo '{"session_id":"c","tool_name":"Bash","tool_input":{"command":"pytest"},"error":"Exit code 1\nFAILED test_a"}' | python3 $S failure
echo '{"session_id":"c","tool_name":"Bash","tool_input":{"command":"cargo build"},"error":"Exit code 101\nerror[E0308]"}' | python3 $S failure
# second call emits: failed 2 times ... same signature: "exit code <n>"
```

**C4: concurrent writers.** Start 12 `failure` hooks (distinct commands) and one Edit `success` hook in parallel with `&`, `wait`, then read `hdc-state-<sid>.json`. Expected `edit_epoch=1` with 12 calls. Across 40 trials: epoch 0 in 3, invalid JSON in 1, fewer than 12 calls in 39.

**C1, C2, C3: real session.** Build a minimal plugin whose hooks for PreToolUse, PostToolUse and PostToolUseFailure run `cat >> payloads.jsonl`. Load it with `--plugin-dir` next to this plugin, then run `claude -p` with the 10-step prompt from [How this was checked](#how-this-was-checked). In the log, look for:
- no Edit payloads at all (C1)
- `grep` arriving as `PostToolUse` with `returnCodeInterpretation` (C2)
- subagent payloads carrying the parent's `session_id` and `scratchpad_dir`, with the subagent's first `false` denied (C3)
