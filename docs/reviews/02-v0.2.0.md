## 1. Correctness

### R1. Porcelain `git diff` takes `index.lock` and makes concurrent git writes fail — BLOCKING

- **Where:** [scripts/hdc_hooks.py:178](hierarchy-of-defect-controls/scripts/hdc_hooks.py#L178), called from `tree_fingerprint` on every gate, success and failure hook.
- **Failure mode:** porcelain `git diff` refreshes the index and takes `.git/index.lock`, even with `GIT_OPTIONAL_LOCKS=0`. Any git write at the same moment fails with `fatal: Unable to create '.git/index.lock': File exists`. Sources of such writes:
  - a parallel Bash `git add`/`commit`/`rebase`
  - a subagent's git command
  - the user's IDE git integration
  - the user committing by hand

  The plugin's docstring ([hdc_hooks.py:43](hierarchy-of-defect-controls/scripts/hdc_hooks.py#L43)) promises it can "never break a session"; this breaks work outside its scope.
- **Confirmed (ran):** 2,000-file repo; the foreground loop runs `touch <random file>; echo >> f1.txt; git add -A && git commit`, 400 times per arm.

  | Background loop | Commits failed on `index.lock` |
  |---|---|
  | none (control) | 0 / 400 |
  | v0.2.0 `fingerprint` mode | 38 / 400 |
  | `fingerprint` with `GIT_OPTIONAL_LOCKS=0` | 15 / 400 |

  Per-command isolation, each command looping alone with `GIT_OPTIONAL_LOCKS=0`, 250 commits per arm:

  | Background command | Failures |
  |---|---|
  | `git status --porcelain=v1 -z --untracked-files=all` | 0 |
  | **`git diff --no-color`** | **198** |
  | `git diff --no-color --cached` | 0 |
  | `git diff-files -p` | 0 |
  | `git diff-index -p --cached HEAD` | 0 |
  | `git rev-parse --show-toplevel HEAD` | 0 |

- **Fix:**
  - Replace `git diff --no-color` with `git diff-files -p`.
  - Replace `git diff --no-color --cached` with `git diff-index -p --cached HEAD`.
  - Run every git call with `GIT_OPTIONAL_LOCKS=0` in the environment.
- **Checked (ran):** the plumbing fingerprint does not change when `sed -i` rewrites a tracked file without changing its content, whether that file is clean or already dirty, so the no-op detector keeps working. It does change on a real edit.
- **Caveat (reasoned):** `git diff-index … HEAD` fails in a repo with no commits (unborn `HEAD`). Handle that case, for example by using the empty-tree hash or skipping the cached diff, instead of falling back to the edit counter.

### R2. The no-op detector reports real edits as "the replacement matched nothing" — BLOCKING

- **Where:** [scripts/hdc_hooks.py:370-384](hierarchy-of-defect-controls/scripts/hdc_hooks.py#L370-L384), with `INPLACE_EDIT_RE` at [scripts/hdc_hooks.py:60-62](hierarchy-of-defect-controls/scripts/hdc_hooks.py#L60-L62).
- **Failure mode:** the detector compares the repo fingerprint before and after the command. Any in-place edit whose effect is outside the fingerprint is recorded as a failure, and the model is told something false.
- **Confirmed:** every row below exited 0 and got "reported success but the working tree is unchanged: the replacement matched nothing".

  | Command | What actually happened | Confirmed |
  |---|---|---|
  | `sed -i 's/BAD/OK/' .env` (`.env` gitignored) | `.env` now contains `OK` | ran |
  | `sed -i 's/a/b/' /abs/path/outside-repo.txt` | file now contains `b` | ran |
  | `sed -i 's/foo/bar/' x.txt && git commit -qam wip` | `git show HEAD:x.txt` is `bar`; tree clean before and after | ran, real session (step 13) |
  | `git apply --check ../fix.patch` | nothing, by design (dry run) | ran |

- **Harm:** the model is told a successful edit did nothing, and may redo or undo it. The false failure also counts toward the gate threshold.
- **Fix:**
  - **`sed -i` / `perl -pi`:** split the command with `shlex`. Hash the content of every operand that is an existing file in PreToolUse (keyed by `tool_use_id`) and compare in PostToolUse. This works for gitignored and out-of-repo files and needs no git.
  - **`git apply` / `patch`:** keep the tree fingerprint, with `HEAD` added per R3. Skip `--check`, `--dry-run`, `--stat`, `--numstat` and `--summary`.
  - **Compound commands** (`&&`, `||`, `;`, `|`, newlines): skip detection entirely. The detector can't tell which part changed what.

### R3. The fingerprint omits `HEAD`, ignored files and out-of-repo files, so real fixes don't reopen the gate — BLOCKING

- **Where:** [scripts/hdc_hooks.py:157-191](hierarchy-of-defect-controls/scripts/hdc_hooks.py#L157-L191) (`tree_fingerprint`, `current_marker`).
- **Failure mode:** when git is available, the marker is only a hash of `git status` plus the diffs.
  - **Clean trees are indistinguishable.** Every clean tree hashes to `da39a3ee5e6b4b0d3255bfef95601890afd80709`, the SHA-1 of empty input; that exact value is the recorded marker in the real session's state file. A fix that arrives by `git checkout`, `git pull`, `git reset --hard` or `git stash pop` onto a clean tree leaves the marker unchanged.
  - **The edit counter is ignored when git is present.** An Edit or Write to a gitignored or out-of-repo file therefore no longer reopens the gate. That is a regression from v0.1.0.
- **Confirmed:**
  - **Real session (steps 7–11):** `python3 check.py` failed twice (exit 3). The model then used the Edit tool on gitignored `.env` (BAD → OK). The retry was denied with "the working tree is unchanged since the last failure", although `check.py` now exits 0.
  - **Ran:** `sh t.sh` failed twice on `main`; `git checkout -q fix` succeeded; the retry was denied, although `sh t.sh` now exits 0.
- **Fix:** marker = plumbing fingerprint (R1) + `git rev-parse HEAD` + `edit_epoch`. Any of the three changing reopens the gate.
- **Remaining gap to document (reasoned):** environment changes via Bash (`pip install`, `docker start`, `export`) change none of the three. The only way out is a new user message. Add this to README "Known gaps".

### R4. Every tool call pays for two fingerprints, run one at a time under the session lock

- **Where:** [scripts/hdc_hooks.py:305](hierarchy-of-defect-controls/scripts/hdc_hooks.py#L305) (gate), [scripts/hdc_hooks.py:365](hierarchy-of-defect-controls/scripts/hdc_hooks.py#L365) (success).
- **Failure mode:** the gate and success hooks compute the fingerprint unconditionally, including for Read, Grep and Glob, and hold the `flock` while they do. Parallel tool calls wait on one another.
- **Confirmed (ran):** warm cache; "6 parallel" is six `gate` hooks started together, as for one batch of parallel Reads.

  | Repo | Fingerprint | One gate hook | One success hook | 6 parallel gates: last finishes |
  |---|---|---|---|---|
  | 300 tracked, 5 dirty, 10 untracked | 0.05 s | 0.04 s | 0.05 s | 0.09 s |
  | 20k tracked, 200 dirty, 2k untracked | 0.12 s | 0.11 s | 0.11 s | 0.45 s |
  | 120k tracked, 2k dirty, 40k untracked | 0.7–0.85 s | 0.69 s | 0.61 s | 3.2 s |

  None exceeded the 10 s hook timeout, and the marker never flipped between git and the edit counter across 5 runs per repo.
- **Worst case (reasoned):** four git calls at `GIT_TIMEOUT=3` can take ~12 s, above the 10 s hook timeout. A killed hook loses its bookkeeping.
- **Fix:** compute the fingerprint only when needed:
  - **gate:** when this agent has a recorded call at or above `THRESHOLD` for this key, or the call arms the no-op detector
  - **success:** when a before-snapshot exists for this `tool_use_id`
  - **failure:** always

  Where possible, compute it before taking the lock.

### R5. Error signatures still collide for test runners and commands with no output

- **Where:** [scripts/hdc_hooks.py:97-104](hierarchy-of-defect-controls/scripts/hdc_hooks.py#L97-L104).
- **Failure mode:** the signature is `exit N:` plus the first non-empty output line.
  - **Test runners:** pytest's first line is always `============================= test session starts ==============================`, so any two failing pytest commands share a signature.
  - **No output:** every failing command with no output (`false`, `test -f x`, `cmp -s`) gets `exit N:`.
- **Confirmed:**
  - ran: `pytest tests/test_a.py`, then `pytest tests/test_b.py` → "failed 2 times … same signature: "exit 1: ===…"
  - real session: `false` recorded as `exit 1:`
- **Why the tests miss it:** [test/run_tests.py:161-164](hierarchy-of-defect-controls/test/run_tests.py#L161-L164) only uses first lines that already differ.
- **Fix (suggested):** skip lines made only of punctuation or box-drawing characters. Prefer the first line matching `error|fail|exception|fatal|traceback` (case-insensitive), else the first remaining line. For output-less failures, include the tool name and command's first word in the reminder's signature key; the gate already keys on the exact call.

### R6. A per-run id in the error stops the gate from ever arming

- **Where:** `normalise_line`, [scripts/hdc_hooks.py:75-85](hierarchy-of-defect-controls/scripts/hdc_hooks.py#L75-L85); the count reset is at [scripts/hdc_hooks.py:287](hierarchy-of-defect-controls/scripts/hdc_hooks.py#L287).
- **Failure mode:** only all-digit tokens are normalised. Hex ids, request ids, UUIDs and container ids differ between runs, so each failure looks new and the count resets to 1.
- **Confirmed (ran):** `./deploy.sh` failed four times with `Exit code 1\nrequest <7f3a9bc2|a91c03de|c0ffee42|d15ea5e7>: upstream refused connection`. The gate allowed all four attempts.
- **Severity:** low; this fails open.
- **Fix:** normalise UUIDs and hex runs of 7 or more characters that contain at least one digit.

### R7. Test coverage misses the new failure modes

- **Where:** [test/run_tests.py](hierarchy-of-defect-controls/test/run_tests.py).
- **Concurrency test runs outside git.** [Lines 216-233](hierarchy-of-defect-controls/test/run_tests.py#L216-L233) use `self.h`, which runs in a non-git directory, so the fingerprint and lock path is never tested under contention. Traced.
- **No tests for:** gitignored or out-of-repo files, `HEAD` moves, compound commands, dry-run flags, lock contention with a concurrent git write, or the pytest-banner signature.
- **`test_documented_gaps` can't fail** ([lines 291-303](hierarchy-of-defect-controls/test/run_tests.py#L291-L303)). It asserts the length of a literal list, yet counts toward "22 tests" ([README.md:27](hierarchy-of-defect-controls/README.md#L27)). See F4.

## 2. Framework consistency

### F1. The no-op detector's "Engineer, narrow" label is half right

- **Where:** [README.md:8](hierarchy-of-defect-controls/README.md#L8).
- **What is Engineer:** recording the no-op as a failure is deterministic. It arms the gate against identical retries of the no-op command.
- **What isn't:** the defect it targets is the model proceeding as if the replacement happened. The only thing working against that is the `additionalContext` message, which the model must read and act on. That is Administer.
- **Correction to round 1:** round 1 proposed this check and said it closed the gap. It closes the retry half only.
- **Correct label:** "Engineer for the identical-retry loop; Administer for the silent no-op itself."

### F2. The gate's label is right, but its scope is overstated

- **Where:** [README.md:35](hierarchy-of-defect-controls/README.md#L35), [scripts/hdc_hooks.py:31-35](hierarchy-of-defect-controls/scripts/hdc_hooks.py#L31-L35).
- **The claim:** "a fix applied by sed, a generator, an MCP file server, or the user's IDE reopens the gate".
- **The reality (R3):** true only for tracked or non-ignored files inside the repo, and not for `HEAD` moves or environment changes. Correct the text after the R3 fix to state exactly what reopens the gate.

### F3. The package discloses that it breaks its own real-payload rule

- **Where:** [docs/CLAUDE.md:19](hierarchy-of-defect-controls/docs/CLAUDE.md#L19) requires that "any hook or check you add must be exercised against a real payload before it is relied on". [README.md:29](hierarchy-of-defect-controls/README.md#L29) and [test/run_tests.py:5-12](hierarchy-of-defect-controls/test/run_tests.py#L5-L12) say the fixtures are "reconstructed, not captured".
- **Assessment:** stating it is honest, but a disclosure is a note (Administer) standing in for an unmet check.
- **Fix:** commit one captured payload per event (PreToolUse, PostToolUse, PostToolUseFailure, UserPromptSubmit, plus a subagent PreToolUse carrying `agent_id`) as JSON fixtures, and build the test payloads from them. [Real session](#real-session) describes a capture setup.

### F4. `test_documented_gaps` is documentation dressed as a test

- **Where:** [test/run_tests.py:291-303](hierarchy-of-defect-controls/test/run_tests.py#L291-L303).
- **Assessment:** this is the pattern [docs/CLAUDE.md:18](hierarchy-of-defect-controls/docs/CLAUDE.md#L18) names: something that looks like a control but only states things. Move the list to the README and drop it from the test count.

## Reproduction

### Direct harness

Simulates one tool call: PreToolUse `gate` → run the real command → `success` or `failure`, with the field names seen in real 2.1.270 payloads.

```python
import json, os, subprocess, tempfile
S = "hierarchy-of-defect-controls/scripts/hdc_hooks.py"   # adjust to an absolute path
base = tempfile.mkdtemp()
N = [0]

def sh(cmd, cwd): return subprocess.run(cmd, shell=True, cwd=cwd, capture_output=True, text=True)
def hook(mode, p): return subprocess.run(["python3", S, mode], input=json.dumps(p), capture_output=True, text=True).stdout

def mkrepo(name):
    r = os.path.join(base, name); os.makedirs(r)
    sh("git init -q -b main && git config user.email t@t && git config user.name t && "
       "printf 'foo\\n' > x.txt && printf '.env\\n' > .gitignore && git add -A && git commit -qm init", r)
    return r

def common(r, sid, tool, ti, agent=None):
    N[0] += 1
    d = {"session_id": sid, "cwd": r, "scratchpad_dir": base, "tool_name": tool,
         "tool_input": ti, "tool_use_id": f"toolu_{N[0]}"}
    if agent: d["agent_id"] = agent
    return d

def bash(r, sid, cmd):
    p = common(r, sid, "Bash", {"command": cmd})
    if "deny" in hook("gate", {**p, "hook_event_name": "PreToolUse"}): return "DENIED", ""
    res = sh(cmd, r)
    if res.returncode == 0:
        out = hook("success", {**p, "hook_event_name": "PostToolUse",
                               "tool_response": {"stdout": res.stdout, "stderr": res.stderr, "interrupted": False}})
    else:
        out = hook("failure", {**p, "hook_event_name": "PostToolUseFailure",
                               "error": f"Exit code {res.returncode}\n{res.stdout}{res.stderr}".strip()})
    return f"exit={res.returncode}", (json.loads(out)["hookSpecificOutput"]["additionalContext"] if out else "")
```

### Lock contention (R1)

```bash
S=/abs/path/hierarchy-of-defect-controls/scripts/hdc_hooks.py
R=$(mktemp -d) && cd $R && git init -q -b main && git config user.email t@t && git config user.name t
for i in $(seq 1 2000); do echo $i > f$i.txt; done && git add -A && git commit -qm init
arm() {  # $1 label, $2 env assignment or "", $3 1=run background loop
  rm -f .stop
  if [ "$3" = 1 ]; then ( while [ ! -f .stop ]; do touch f$((RANDOM%2000+1)).txt
      echo "{\"cwd\":\"$R\"}" | env $2 python3 $S fingerprint >/dev/null; done ) & fi
  bad=0
  for i in $(seq 1 400); do touch f$((RANDOM%2000+1)).txt; echo $i >> f1.txt
    out=$(git add -A 2>&1 && git commit -qm c$i 2>&1) || { echo "$out" | grep -q index.lock && bad=$((bad+1)); }; done
  touch .stop; wait; echo "$1: $bad/400"
}
arm control "" 0; arm v0.2.0 "" 1; arm optional-locks-off GIT_OPTIONAL_LOCKS=0 1
```

For the per-command breakdown, replace the hook call in the background loop with a single git command (e.g. `env GIT_OPTIONAL_LOCKS=0 git diff --no-color`).

### Real session

- **Capture plugin:** a minimal plugin whose PreToolUse, PostToolUse, PostToolUseFailure and UserPromptSubmit hooks run `cat >> payloads.jsonl`.
- **Loading:** pass it with `--plugin-dir` next to this plugin: `claude -p --allowedTools "Bash Edit Read Agent" --max-turns 40 --output-format json`.
- **Working directory:** a git repo containing tracked `x.txt` (`foo`), a `.gitignore` listing `.env`, `.env` containing `BAD`, and a tracked `check.py` that exits 0 only when `.env` is `OK`.

Prompt used:

> This is a hook test harness. Do exactly these steps in order, one tool call per message, never parallel, never vary a command, never add comments to commands. If a step is blocked or errors, record the exact message and continue. 1) Bash: false 2) Bash: false 3) Bash: false 4) Bash: sed -i 's/zzz/yyy/' x.txt 5) same as 4 6) same as 4 7) Bash: python3 check.py 8) same as 7 9) Read .env 10) Edit .env replacing old_string BAD with new_string OK 11) Bash: python3 check.py 12) Launch one general-purpose subagent with the Agent tool whose only job is to run Bash: false once and report the exact result. 13) Bash: sed -i 's/foo/bar/' x.txt && git commit -qam wip. Finally, report for each step: ran / errored / blocked, the exact hook or error messages, and any additional context you received from hooks.

Then resume the session with `claude -p --resume <session_id> "Run exactly Bash: false (one call, no variation) and report the exact result, including whether it was blocked."`. This fires `UserPromptSubmit` and exercises the reset.
