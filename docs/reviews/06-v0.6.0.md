# Review round 6: hierarchy-of-defect-controls v0.6.0

Adversarial re-review, 2026-10-05, of `main` at merge `6c590de` (commit `5e6017e`, "v0.6.0: indicators, an API RP 754 analog"). Previous rounds: [01](01-v0.1.0.md), [02](02-v0.2.0.md), [03](03-v0.3.0.md), [04](04-v0.4.0.md), [05](05-v0.5.0.md).

Finding IDs stay stable across rounds. New IDs this round: R8–R11, F3, F4.

**Verdict: ship.** No blocking defects. The hooks are byte-identical to 0.5.1 on every case in the rounds 2–5 harnesses (56 cases, 0 differing outputs), the round-5 retest checklist passes, and the report's numbers matched a live Claude Code 2.1.289 session line for line.

**Should fix, in order.** None causes a false statement to the model or a wrong denial.
- **R8 (low–medium):** `DENY_RE` cuts the signature at the first `")`. A loop whose error line contains a quoted call, such as pytest's `assert parse("x") == 1`, is reported as two episodes instead of one, with depth undercounted. Episodes are the report's primary unit.
- **R9 (low):** the eager `import traceback` costs 12–15 ms on every hook invocation (Python 3.14, where `traceback` pulls in `_colorize`). The unarmed gate went from 39 ms in 0.5.1 to 54 ms; a lazy import inside the `except` restores 41 ms. Two invocations per tool call.
- **R10 (low):** a corrupt state file logs one `state_corrupt` record per unarmed gate call, because the unlocked fast path never rewrites the file. Three `Read`s produced three records plus a fourth from the hook that healed it. `docs/indicators.md:67` says "each append one JSON line".
- **R11 (low):** `log_event` follows symlinks: an `HDC_EVENTS` symlink to any user-writable file is appended to, and a dangling symlink has its target created.
- **F3 (low, docs):** four claims do not hold as written (stale mount cannot block; "two of them every commit carries the trailer"; one record per corruption; the bare-vs-wrapped deny form has only been observed in `-p` sessions).
- **F4 (low, tests):** `test_off_by_default` passes against a mutant that logs to a default path when `HDC_EVENTS` is unset; the FIFO test cannot tell `O_NONBLOCK` from the `S_ISREG` check (either alone passes it).
- **Hygiene:** `test/run_tests.py` now imports the scripts in-process, so every run leaves `scripts/__pycache__` behind, which round 5 checked for explicitly. Gitignored, so harmless to the marketplace install.

**Recommendation on further rounds.** The hook logic is unchanged and re-verified live. The report is a parser over an undocumented format; what will break it is a Claude Code upgrade, not an adversary. Round 7 can be the targeted checklist at the end, plus a re-capture of fixtures after the next upgrade that changes the transcript format.

## 1. Correctness

### R8. `DENY_RE` truncates the signature at the first `")` — should fix, low–medium

- **Where:** [scripts/hdc_hooks.py:93-94](../../scripts/hdc_hooks.py#L93-L94). The deny text is `… with the same error ("<sig>") and nothing has changed …`, and the regex takes `(?P<sig>.*?)"\)` lazily. `REMINDER_RE` ([:95-96](../../scripts/hdc_hooks.py#L95-L96)) takes `(?P<sig>.*)"\. The Hierarchy` greedily, so the two disagree whenever the signature itself contains `")`.
- **Failure scenario:** any error line with a quoted call argument. `normalise_line` keeps quotes and parentheses, so `ValueError("bad input") raised by foo`, pytest's `E   assert parse("x") == 1`, or Node's `Error("…")` all produce a signature containing `")`. The report then keys the reminder under the full signature and the deny under the truncated one ([scripts/hdc_report.py:157,172](../../scripts/hdc_report.py#L157)), so one loop becomes two episodes of depth 1 each: episode count up, `max_depth` down, and a reminder-then-deny-then-deny loop still shows `past_gate` correctly but under a different episode from its reminder.
- **Confirmed (ran):** two failures of `./x` with error `Exit code 1\nValueError("bad input") raised by foo`, then the gate. The hooks emit reminder signature `exit 1: valueerror("bad input") raised by foo` and the deny parses as `exit 1: valueerror("bad input`. Fed to `hdc_report.build` as one turn: `episodes 2, max_depth 1` (expected 1 and 2).
- **Fix:** anchor on the text that follows the signature in every version since 0.3: `\("(?P<sig>.*)"\) and `. Checked against both fixtures and the case above: `exit 1:`, `no-op in-place edit: working tree unchanged`, `exit 1: bash sh`, and the full quoted signature all parse (ran). Add the case to `ReportDrift`.

### R9. Eager `import traceback` slows every hook invocation — should fix, low

- **Where:** [scripts/hdc_hooks.py:75](../../scripts/hdc_hooks.py#L75); used only at [:649](../../scripts/hdc_hooks.py#L649) inside the `except` in `main()`.
- **Measured (ran):** unarmed `gate` on a `Read`, mean of 40 runs, twice: 0.5.1 38.9 / 39.6 ms; 0.6.0 54.6 / 53.7 ms; 0.6.0 with the import moved into the `except` 41.1 / 40.4 ms. `python3 -X importtime` attributes 12.0 ms to `traceback`, 9.4 ms of it `_colorize` (Python 3.14.4). `stat` and `time` are built-in and free.
- **Effect:** `PreToolUse` and `PostToolUse` run on every tool call, so about 30 ms per tool call, on the path the package says must spawn nothing ([docs/plugin.md:63](../../docs/plugin.md#L63)). Not a decision change; the round-5 "no git on the fast path" check still passes and the `test_10_no_git_spawned_when_nothing_armed` 0.5 s bound is far away.
- **Fix:** `import traceback` inside the `except Exception as exc:` block. The `tempfile` import (4.7 ms, present since 0.1) is the next largest and only `state_path` uses it; `tempfile.gettempdir()` could be replaced with the same env/`/tmp` lookup, but that is optional.

### R10. A corrupt state file is logged once per unarmed gate call, not once — should fix, low

- **Where:** [scripts/hdc_hooks.py:429-444](../../scripts/hdc_hooks.py#L429-L444) logs from `peek_state`; [:534](../../scripts/hdc_hooks.py#L534) calls it unlocked on every `gate`, and the fast path returns at [:538-539](../../scripts/hdc_hooks.py#L538-L539) without rewriting the file. Only a locked path (`State.__exit__`) heals it.
- **Confirmed (ran):** state file set to `{corrupt`, `HDC_EVENTS` set, three `gate` calls for an unarmed `Read`: three `state_corrupt` records, file still corrupt. One `success` call: a fourth record and the file is healed. A `failure` hook on a corrupt file writes exactly one.
- **Effect:** Tier 4 is "counts, not a rate" and "any non-zero count is a finding" ([docs/indicators.md:39](../../docs/indicators.md#L39)), so this inflates a finding rather than creating one. In practice `PostToolUse` follows every `PreToolUse`, so the usual outcome is two records per corruption, not one. `test_corrupt_state_is_recorded_and_healed` ([test/run_tests.py:882-889](../../test/run_tests.py#L882-L889)) only exercises `reset`, a locked path.
- **Fix:** log only from the locked read (pass `log=False` from `mode_gate`'s peek, or log in `State.__enter__` after `peek_state`), and extend the test to three unarmed gates. Then `docs/indicators.md:67` is true.

### R11. `log_event` follows symlinks — low

- **Where:** [scripts/hdc_hooks.py:391](../../scripts/hdc_hooks.py#L391) uses `os.stat`, which follows links, and [:402](../../scripts/hdc_hooks.py#L402) opens with `O_CREAT` and no `O_NOFOLLOW`.
- **Confirmed (ran):** `HDC_EVENTS` → symlink to a 0644 file: one JSON line appended to that file. `HDC_EVENTS` → dangling symlink: the target is created.
- **Risk:** small. `HDC_EVENTS` is set by the user, the hook runs as the user, and an agent that can replace the file with a symlink can write the target directly. The exposure is a hook that *silently* writes to a file nobody intended on a path the user believed was a log. See [Harm](#3-harm).
- **Fix:** `os.lstat` plus `os.O_NOFOLLOW` (Linux and macOS both have it). Two lines.

- **Report and Tier 4 log:** "indicator, not a control" ([docs/plugin.md:11-12](../../docs/plugin.md#L11-L12)). Right: neither decides anything, and both the README and `plugin.md` say nothing they compute reaches the model.

### F3. Statements that do not hold as written — should fix, low

- **[docs/indicators.md:67](../../docs/indicators.md#L67) and [scripts/hdc_hooks.py:380-383](../../scripts/hdc_hooks.py#L380-L383):** "the write cannot block" / "a FIFO or a stale mount cannot hold a hook until its timeout". `O_NONBLOCK` affects FIFOs and devices, not regular files, and `os.stat` at `:391` runs before it on a hard-mounted stale NFS path and blocks there. The FIFO case is handled, by the `S_ISREG` check, before `O_NONBLOCK` is reached (F4 shows either guard alone passes the test). A hung filesystem can hold this hook exactly as it can hold the state file, so this is not new exposure, but the sentence claims an immunity the code does not have. Reword to "a FIFO is refused; a hung filesystem can still block it, as it can the state file".
- **[docs/indicators.md:26](../../docs/indicators.md#L26):** "in two of them every commit carries the trailer". On this machine 7 of the 8 repos with any trailer commit have the trailer on every commit (55/55, 7/7, 2/2, 10/10, 89/89, 175/175, 21/21; the eighth is 13/48). The conclusion the sentence supports is stronger than stated: the trailer separates agent changes from nothing in almost all of them.
- **[docs/indicators.md:67](../../docs/indicators.md#L67):** "a corrupt state file each append one JSON line". See R10.
- **[docs/indicators.md:65](../../docs/indicators.md#L65) and [scripts/hdc_report.py:32-33](../../scripts/hdc_report.py#L32-L33):** "between 2.1.270 and 2.1.289 the stored form of a deny changed". Every deny stored on this machine comes from a `-p` session (16 bare at 2.1.270, 4 wrapped at 2.1.289). No interactive-session deny exists here, so whether the change is by version or by mode is not established, and the versions in between (2.1.273–2.1.287 account for most entries here) have no deny at all. Say "observed in `-p` sessions". The entries do carry Claude Code's own `version` field; the report could print the versions it saw, which would make "re-capture after an upgrade" a prompt instead of a reminder.

### F4. Test gaps — should fix, low

- **`test_off_by_default` ([test/run_tests.py:865-869](../../test/run_tests.py#L865-L869)):** asserts only that its own scratch path has no records. A mutant that replaces `os.environ.get("HDC_EVENTS")` with `… or "/tmp/hdc-default-events.jsonl"` passes the whole `Tier4` class (ran). The claim at `docs/plugin.md:37`, "the Tier 4 log is off by default", is therefore not protected. Fix: with `HDC_EVENTS` unset, run the broken hook under `strace -e openat` or, cheaper, import `hdc_hooks` in-process, monkeypatch `os.open` to raise, and call `log_event`.
- **`test_fifo_target_never_blocks_and_deny_survives` ([:891-897](../../test/run_tests.py#L891-L897)):** removing `O_NONBLOCK` passes (the `S_ISREG` check refuses the FIFO first); removing the `S_ISREG` check also passes (`O_WRONLY|O_NONBLOCK` on a reader-less FIFO fails with `ENXIO` at once). The two guards are each other's backup, which is fine, but the test cannot tell whether either is present. If the doc keeps citing both, add a `/dev/null`-style non-regular target that `O_NONBLOCK` would not refuse.
- **Hygiene, `__pycache__`:** [test/run_tests.py:633-635](../../test/run_tests.py#L633-L635) imports `hdc_hooks` and `hdc_report` in-process, so `scripts/__pycache__/*.cpython-314.pyc` appear on every run. The subprocess calls already pass `-B`; add `sys.dont_write_bytecode = True` before the imports.
