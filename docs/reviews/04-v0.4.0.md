## 1. Correctness

### R2c. The patch branch reports real patches as no-ops — BLOCKING

- **Where:**
  - `patch_targets` [scripts/hdc_hooks.py:246-269](hierarchy-of-defect-controls/scripts/hdc_hooks.py#L246-L269)
  - `patch_plan` [scripts/hdc_hooks.py:272-319](hierarchy-of-defect-controls/scripts/hdc_hooks.py#L272-L319)
  - dispatch [scripts/hdc_hooks.py:358-360](hierarchy-of-defect-controls/scripts/hdc_hooks.py#L358-L360)
  - comparison [scripts/hdc_hooks.py:609-612](hierarchy-of-defect-controls/scripts/hdc_hooks.py#L609-L612)
- **Failure mode:** the detector hashes only the file paths it parses from `---`/`+++` header lines, resolved against payload `cwd`, and it checks only working-tree contents. Every row below exited 0, actually changed something, and got "reported success but its target is byte-identical afterwards: the replacement matched nothing. Recorded as failure 1 of this call."

  | Command | What actually changed | Why it was misreported | Confirmed |
  |---|---|---|---|
  | `git apply --cached ../n6.patch` | index: `x.txt \| 2 +-` staged | the working-tree copy is unchanged; the index is not checked | ran, real session (steps 15–16) |
  | `git apply ../n7a.patch` (pure rename, `similarity index 100%`) | `x.txt` renamed to `renamed.txt` | no `---`/`+++` lines, so the plan is `{}`, which [line 611](hierarchy-of-defect-controls/scripts/hdc_hooks.py#L611) treats as "always a no-op" | ran |
  | `git apply ../n7b.patch` (mode change only) | `x.txt` became executable | no `---`/`+++` lines, so `{}`; file mode is not hashed | ran |
  | `git apply ../n7c.patch` (`GIT binary patch`) | `img.bin` bytes `0001…` → `fffe…` | no `---`/`+++` lines, so `{}` | ran |
  | `patch src/foo.c < ../n8.patch` (headers `--- foo.c.orig` / `+++ foo.c`) | `src/foo.c`: `int a = 1;` → `int a = 2;` | explicit target operand ignored; header basenames resolve to nonexistent `./foo.c.orig` and `./foo.c`, whose hash is `None` before and after, which counts as unchanged | ran |
  | `git apply ../sub.patch` with `cwd` = `repo/sub` (header `+++ b/sub/x.txt`) | `sub/x.txt`: `foo` → `qux` | path resolved against `cwd` (`repo/sub/sub/x.txt`, nonexistent) instead of the repo top: `None` before and after | ran, real session (steps 18–20) |

- **Harm:** the model is told a successful patch did nothing, and the false failure counts toward a denial of an identical call. In the real session the model caught the `--cached` contradiction only because the next scripted step showed the staged diff.
- **Why the branch catches almost nothing (ran).** A patch re-applied after it already applied fails in every form tested, with no tty:

  | Command | First run | Second run (already applied) |
  |---|---|---|
  | `git apply ../re.patch` | 0 | **1** ("patch does not apply") |
  | `patch -p1 < ../re.patch` | 0 | **1** ("Reversed (or previously applied) patch detected! Assume -R? [n]") |
  | `patch -p1 -i ../re.patch` | 0 | **1** |
  | `patch -N -p1 -i ../re.patch` | 0 | **1** ("Skipping patch") |
  | `patch -f -p1 -i ../re.patch` | 0 | **1** ("Hunk #1 FAILED") |
  | empty patch: `git apply --allow-empty`, `patch -i` | 0 | 0 |

  A repeated patch therefore arrives as PostToolUseFailure, and the gate handles it without the detector. The package's own test says the same ([test/run_tests.py:314-315](hierarchy-of-defect-controls/test/run_tests.py#L314-L315)): "the only successful no-op patch is an empty one under --allow-empty". The branch's only true positive is an empty patch. Its false positives are the six rows above, following the gitignored and out-of-repo cases in rounds 2 and 3.

- **Recommended fix (Eliminate): remove `git apply` and `patch` from the no-op detector.**
  - **Code:** delete the dispatch at lines 358-360, plus `patch_plan`, `patch_targets` and `DRY_RUN_FLAGS`. Keep `sed -i`/`perl -pi`, which this round confirmed correct in real use.
  - **Tests:** convert the patch tests ([test/run_tests.py:298-319](hierarchy-of-defect-controls/test/run_tests.py#L298-L319), [346-369](hierarchy-of-defect-controls/test/run_tests.py#L346-L369), [379-382](hierarchy-of-defect-controls/test/run_tests.py#L379-L382)) into assertions that a patch is never flagged. Add the six cases above.
  - **Docs:** update [README.md:8](hierarchy-of-defect-controls/README.md#L8), [README.md:58](hierarchy-of-defect-controls/README.md#L58), [docs/CLAUDE.md:29](hierarchy-of-defect-controls/docs/CLAUDE.md#L29) and the docstring ([scripts/hdc_hooks.py:46-50](hierarchy-of-defect-controls/scripts/hdc_hooks.py#L46-L50)) to name only `sed -i` and `perl -pi`.
  - **Rationale:** this applies the package's own rule at [docs/CLAUDE.md:20](hierarchy-of-defect-controls/docs/CLAUDE.md#L20): scope a narrow control as tightly as the pattern allows, and say what would justify removing it. Three rounds of false positives against a true-positive surface of "empty patch" is that justification.
- **Alternative, if the branch is kept.** All six rules are needed; each closes one row above.
  1. If every parsed target is missing both before and after, skip rather than flag. (N8, N9)
  2. Treat `{}` as a no-op only when the patch file has no `diff --git`, `@@`, `GIT binary patch`, `rename from` or `old mode` lines. (N7)
  3. Skip `--cached`, or compare the index too, e.g. `git diff-index --cached` before and after. (N6)
  4. Take targets from `diff --git a/X b/Y` lines as well, and include `st_mode` in the per-file hash. (N7)
  5. Resolve `git apply` paths against `git rev-parse --show-toplevel`. (N9)
  6. For `patch`, treat the first positional argument as the target when the patch comes from `<` or `-i`. (N8)

  This keeps growing a patch parser to protect a case the failure path already covers, so removal is the recommendation.

## Reproduction

### Harness

Same as rounds 2 and 3, with a `cwd` argument and an optional synthetic error text. It simulates PreToolUse `gate` → the real command → `success` or `failure`, using real payload field names.

```python
import json, os, subprocess, tempfile
S = "/abs/path/hierarchy-of-defect-controls/scripts/hdc_hooks.py"
base = tempfile.mkdtemp()
N = [0]

def sh(cmd, cwd): return subprocess.run(cmd, shell=True, cwd=cwd, capture_output=True, text=True)
def hook(mode, p): return subprocess.run(["python3", S, mode], input=json.dumps(p), capture_output=True, text=True).stdout

def mkrepo(name):
    r = os.path.join(base, name); os.makedirs(r)
    sh("git init -q -b main && git config user.email t@t && git config user.name t && "
       "printf 'foo\\n' > x.txt && mkdir -p sub src && printf 'foo\\n' > sub/x.txt && "
       "printf 'int a = 1;\\n' > src/foo.c && git add -A && git commit -qm init", r)
    return r

def bash(cwd, sid, cmd, raw_err=None):
    N[0] += 1
    p = {"session_id": sid, "cwd": cwd, "scratchpad_dir": base, "tool_name": "Bash",
         "tool_input": {"command": cmd, "description": "d"}, "tool_use_id": f"toolu_{N[0]}"}
    if "deny" in hook("gate", {**p, "hook_event_name": "PreToolUse"}): return "DENIED", ""
    res = sh(cmd, cwd)
    if res.returncode == 0:
        out = hook("success", {**p, "hook_event_name": "PostToolUse",
                               "tool_response": {"stdout": res.stdout, "stderr": res.stderr, "interrupted": False}})
    else:
        out = hook("failure", {**p, "hook_event_name": "PostToolUseFailure",
                               "error": raw_err or f"Exit code {res.returncode}\n{res.stdout}{res.stderr}".strip()})
    return f"exit={res.returncode}", (json.loads(out)["hookSpecificOutput"]["additionalContext"] if out else "")
```
